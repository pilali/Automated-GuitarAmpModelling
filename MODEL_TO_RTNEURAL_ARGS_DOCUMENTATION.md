# Command-Line Arguments for `modelToRTNeural.py`

This document provides a detailed description of the command-line arguments accepted by the `modelToRTNeural.py` script. This script is designed to convert trained neural network models, typically those generated by `dist_model.py` or compatible `.nam` files, into an RTNeural-compatible JSON format (or optionally `.aidax`).

The script offers two main modes of operation: either converting a specific, user-provided model file, or automatically identifying and converting the best model from a training session based on a configuration file and saved statistics.

## Arguments

1.  **`--load_model` / `-lm`**
    *   **Description**: Specifies the direct path to a trained model file that is to be converted. This argument is intended for converting a single, specific model.
        *   It can point to a `.json` model file exported by the `dist_model.py` script (e.g., `Results/my_device/model_best.json`).
        *   It can also point to a `.nam` (Neural Amp Modeler) file from other sources, if the script supports its format.
    *   **Behavior if Provided**: If a valid file path is given for `--load_model`, the script will attempt to load and convert this specific model file directly.
        *   In this mode, the arguments `--load_config`, `--results_path`, and the associated logic for automatically selecting the "best" model based on `training_stats.json` are **skipped and ignored**.
        *   The output RTNeural JSON (or `.aidax`) file will be saved in the same directory as the input model file specified by `--load_model`.
    *   **Default**: `''` (empty string). By default, this argument is not used, and the script relies on `--load_config`.

2.  **`--load_config` / `-l`**
    *   **Description**: Specifies the name of a JSON configuration file (e.g., `LSTM-12`, `MyTrainingConfig`, `MyAmpSimSetup`). This configuration file should be located in the directory specified by the `--config_location` argument. This mode is active when `--load_model` is *not* provided.
    *   **Functionality**: When using this argument, the script uses the specified configuration file to:
        *   Retrieve essential model parameters and metadata such as `device` name (which determines the results subdirectory), `unit_type` (e.g., LSTM, GRU), `hidden_size`, `num_layers`, `skip_con` (skip connection or input skip value), and any other `metadata` stored in the config.
        *   Infer the path to the training results. Typically, this path is assumed to be `Results/<device_name>/` (where `<device_name>` is read from the config), unless explicitly overridden by the `--results_path` argument. The script expects to find `training_stats.json`, `model.json`, and `model_best.json` in this results directory.
        *   Automatically identify the best performing model by comparing `model.json` and `model_best.json`. This comparison is based on the `test_lossESR_final` (for `model.json`) and `test_lossESR_best` (for `model_best.json`) values, which are read from the `training_stats.json` file found in the results directory. The model with the lower ESR (Error-to-Signal Ratio) is chosen for conversion.
    *   **Default**: `LSTM-12`

3.  **`--results_path` / `-rp`**
    *   **Description**: Specifies the directory that contains the training results for a model. This argument is relevant only when `--load_model` is *not* provided and the script is operating in the `--load_config` mode. It tells the script where to find `training_stats.json`, `model.json`, and `model_best.json`.
    *   **Behavior if Not Provided**: If this argument is an empty string or not provided, the script constructs the path to the results directory dynamically. It uses the `device` name obtained from the configuration file (specified by `--load_config`) and assumes the results are located in `Results/<device_name>/`.
    *   **Example**: If your results are in `Output/Models/MyGuitarAmp/`, you would set `--results_path Output/Models/MyGuitarAmp/`.
    *   **Default**: `''` (empty string).

4.  **`--config_location` / `-cl`**
    *   **Description**: Specifies the directory where the JSON configuration files (referenced by the `--load_config` argument) are stored.
    *   **Default**: `Configs`

5.  **`--aidax` / `-ax`**
    *   **Description**: This is a boolean optional action flag. If this argument is included in the command, the output file containing the RTNeural-compatible model description will be saved with the `.aidax` extension instead of the default `.json` extension.
    *   **Usage**: Simply add `--aidax` or `-ax` to the command line if you want an `.aidax` file.
    *   **Default**: `False` (If the flag is not present, the output file will have a `.json` extension).

6.  **`--verbose` / `-v`**
    *   **Description**: This is a boolean action flag. If present in the command, it enables verbose output during the script's execution. This means the script will print more detailed information about its operations, such as files being loaded, parsed parameter values, intermediate steps, and status messages. This can be helpful for debugging or understanding the script's flow.
    *   **Usage**: Add `--verbose` or `-v` to the command line to enable these detailed messages.
    *   **Default**: `False` (Verbose output is disabled by default, meaning the script runs more quietly).

## Interaction between `--load_model` and `--load_config`

The script's behavior regarding model loading is primarily determined by whether `--load_model` is used:

*   **If `--load_model` is specified (and is a valid file path):**
    *   The script enters a direct conversion mode for the file provided.
    *   The arguments `--load_config`, `--results_path`, and the entire logic for automatically finding the best model by parsing `training_stats.json` are **completely ignored**.
    *   The output RTNeural file is saved in the same directory as the input model specified by `--load_model`.

*   **If `--load_model` is *not* specified (or is an empty string, its default):**
    *   The script enters a mode where it relies on a training configuration and its associated results.
    *   `--load_config` (and by extension `--config_location` and potentially `--results_path`) are used to locate the model files (`model.json`, `model_best.json`) and the `training_stats.json` file.
    *   The script then determines which model (`model.json` or `model_best.json`) performed better based on the ESR values in `training_stats.json` and converts that model.
    *   The output RTNeural file is typically saved in the identified results directory (e.g., `Results/<device_name>/`).

Understanding this interaction is key to using the script effectively for different conversion scenarios.
