# Comprehensive Guide: Model Training and Conversion

## Introduction

This guide provides a comprehensive overview of the scripts and processes involved in training neural network models for audio processing and converting them for real-time use. It covers data preparation, model training (including conditioned models), and conversion to the RTNeural format. This document consolidates information from various specialized guides into a single, cohesive reference.

We will cover three main Python scripts:
1.  `prep_wav.py`: For preparing audio datasets.
2.  `dist_model.py`: For training the neural network models.
3.  `modelToRTNeural.py`: For converting trained models into a real-time compatible format.

This guide is intended for users who want to understand the end-to-end workflow, from raw audio data to a model ready for deployment with RTNeural.

## `prep_wav.py`

This script is designed to preprocess audio files for tasks such as training neural networks for audio processing, including normalization, denoising, and alignment based on CSV markers.

### Command-Line Arguments

The `prep_wav.py` script accepts the following command-line arguments:

*   `--load_config` / `-l`:
    *   **Description**: Specifies the name of the JSON configuration file to load (e.g., `MyConfig.json`). The script will look for this file in the directory specified by `--config_location`.
    *   **Default**: `RNN-aidadsp-1` (which implies `Configs/RNN-aidadsp-1.json` if `--config_location` is `Configs`)

*   `--config_location` / `-cl`:
    *   **Description**: Specifies the directory where the JSON configuration files are located.
    *   **Default**: `Configs`

*   `--norm` / `-n`:
    *   **Description**: A boolean flag (activates if present). If set, the script performs normalization of target audio tracks to match the volume of the corresponding input audio tracks. This is useful for ensuring consistent loudness levels.
    *   **Default**: `False` (Normalization is not performed unless this flag is explicitly provided)

*   `--denoise` / `-dn`:
    *   **Description**: A boolean flag (activates if present). If set, the script performs noise removal on target audio tracks. This process utilizes the `noisereduce` Python package. The noise profile required for denoising is determined by analyzing regions marked as 'noise' in the CSV file specified in the JSON configuration.
    *   **Default**: `False` (Denoising is not performed unless this flag is explicitly provided)

### JSON Configuration File Structure

The `prep_wav.py` script relies on a JSON configuration file to define various parameters, file paths, and dataset organization. The structure of this JSON file is as follows:

```json
{
  "file_name": "string, base_name_for_output_files",
  "samplerate": "integer, target_sample_rate_for_processing",
  "params": {
    "csv": "string, path_to_csv_file_for_data_splitting",
    "n": "integer, number_of_conditioning_parameters",
    "datasets": [
      {
        "input": "string, path_to_input_raw_audio.wav",
        "target": "string, path_to_target_raw_audio.wav",
        "params": ["float, value_for_param1 (e.g., gain)", "float, value_for_param2 (e.g., tone)"]
      }
      // ... more dataset entries can be added here
    ]
  }
}
```

#### Top-Level Fields:

*   `file_name` (string):
    *   **Description**: This string serves as the base name for all output files generated by the script. For instance, if `file_name` is set to `"my_model"`, the script will produce files like `my_model-input.wav` and `my_model-target.wav`. These processed files will be organized into `Data/train`, `Data/test`, and `Data/val` subdirectories, based on the splits defined in the CSV file.
    *   **Example**: `"audio_experiment_01"`

*   `samplerate` (integer):
    *   **Description**: Defines the target sample rate (in Hz) to which all input and target audio files will be resampled during preprocessing. Timestamps provided in the CSV file (e.g., for blips or noise regions) are also scaled according to this sample rate to ensure correct alignment and processing.
    *   **Example**: `44100`

#### The `params` Object:

This object contains parameters related to data handling, conditioning, and dataset definitions.

*   `csv` (string):
    *   **Description**: Specifies the path to a CSV file. This file is crucial for defining how the audio data is segmented into training, testing, and validation sets. It should also contain timestamps for blips (used for automatic audio alignment between input and target tracks) and can define regions of noise (if the `--denoise` flag is active). The format of this CSV is typically expected to be similar to that of region marker exports from DAWs like Reaper.
    *   **Example**: `"Configs/CsvFiles/guitar_recordings_markers.csv"`

*   `n` (integer):
    *   **Description**: This integer is vital when using conditioned training. It specifies the number of conditioning parameters that will be embedded into the input audio files. For example, if you are training a model conditioned on "gain" and "tone" settings, `n` should be set to `2`. The script will then generate multi-channel input WAV files where the first channel is the original audio, the second channel represents the first parameter, the third channel represents the second parameter, and so on. If no conditioning is being used, this value can be set to `0`. If `n` is greater than 0, each entry in the `datasets` array should have a corresponding `params` list.
    *   **Example**: `2` (indicating two conditioning parameters)
    *   **Note**: If `n` is `0` or the `params` key is missing from a dataset entry, the input audio for that entry will be single-channel (audio only).

*   `datasets` (list of objects):
    *   **Description**: This is an array where each object defines a specific input audio file, its corresponding target audio file, and the associated conditioning parameter values (if any).
    *   Each object within the `datasets` list must contain:
        *   `input` (string):
            *   **Description**: The file path to the raw input audio file (e.g., a direct input (DI) guitar signal).
            *   **Example**: `"RawAudio/GuitarDI/track1_di_clean.wav"`
        *   `target` (string):
            *   **Description**: The file path to the raw target audio file (e.g., the same guitar performance recorded through an amplifier or processed with effects).
            *   **Example**: `"RawAudio/GuitarAmped/track1_amped_distortion.wav"`
        *   `params` (list of floats, optional):
            *   **Description**: This list provides the numerical values for the `n` conditioning parameters associated with this particular input/target audio pair. The order of parameters in this list must be consistent across all entries in the `datasets` array. For example, if `n=2` and the parameters are gain and tone, then `[0.5, 0.7]` would mean gain=0.5 and tone=0.7. This key is required if `n > 0`. If `n` is `0`, this key can be omitted.
            *   **Example (for `n=2`):** `[0.5, 0.7]` (representing, for example, a gain setting of 0.5 and a tone setting of 0.7 for this specific audio pair)

This detailed structure allows for flexible configuration of the audio preprocessing pipeline.

## `dist_model.py`

This script is responsible for training neural network models for audio processing tasks, potentially including conditioned models where additional parameters influence the output.

### Command-Line Arguments

The `dist_model.py` script accepts a wide range of command-line arguments to control various aspects of the training process:

*   `--device` / `-p`:
    *   **Description**: A descriptive label for the device or audio setup being modeled (e.g., "ht1", "my_custom_amp", "pedal_x"). This label is used for naming output directories and files, helping to organize different experiments.
    *   **Default**: `ht1`

*   `--data_location` / `-dl`:
    *   **Description**: Specifies the path to the root "Data" directory. This directory is expected to contain `train`, `val` (validation), and `test` subdirectories, which in turn hold the processed `.wav` files generated by a script like `prep_wav.py`.
    *   **Default**: `./Data`

*   `--file_name` / `-fn`:
    *   **Description**: The base filename of the processed audio data. The script will look for files named `[file_name]-input.wav` and `[file_name]-target.wav` within the `train`, `val`, and `test` subdirectories specified by `--data_location`.
    *   **Default**: `ht1`

*   `--load_config` / `-l`:
    *   **Description**: Specifies the name of a JSON configuration file to load (e.g., `TrainingConfig.json`, `MyExperiment.json`). If provided, arguments from this file will override any other command-line arguments or their defaults. This allows for easy management of complex configurations.
    *   **Default**: `None` (No configuration file is loaded by default)

*   `--config_location` / `-cl`:
    *   **Description**: The directory where JSON configuration files (specified by `--load_config`) are located.
    *   **Default**: `Configs`

*   `--save_location` / `-sloc`:
    *   **Description**: The root directory where trained models, training logs, and evaluation results will be saved. A subdirectory named after the value of `--device` will be automatically created within this location to store all artifacts for a specific model.
    *   **Default**: `Results`

*   `--load_model` / `-lm`:
    *   **Description**: Integer flag (0 or 1). If set to `1`, the script will attempt to load a pre-existing model (e.g., `model.json` and associated weights) from the save path and resume training. If set to `0`, it will start training from scratch, even if a saved model exists.
    *   **Default**: `1` (Attempts to load a model by default)

*   `--seed`:
    *   **Description**: An integer value used to seed random number generators (PyTorch, NumPy, and Python's built-in `random` module). Setting a seed ensures reproducibility of training runs.
    *   **Default**: `None` (No specific seed is set, so results may vary between runs)

*   `--segment_length` / `-slen`:
    *   **Description**: The length of audio segments (in milliseconds) used for training. Audio data is typically chopped into smaller segments to create batches.
    *   **Default**: `500` ms

*   `--epochs` / `-eps`:
    *   **Description**: The maximum number of training epochs to run. An epoch consists of one full pass through the training dataset.
    *   **Default**: `2000`

*   `--validation_f` / `-vfr`:
    *   **Description**: Validation frequency, specified in epochs. The model's performance on the validation set will be evaluated every `N` epochs (where `N` is this value).
    *   **Default**: `2`

*   `--validation_p` / `-vp`:
    *   **Description**: Patience for early stopping. This is the number of consecutive validation checks (as determined by `--validation_f`) without improvement in the validation loss before training is stopped. Setting this to `None` disables early stopping.
    *   **Default**: `25`

*   `--batch_size` / `-bs`:
    *   **Description**: The number of training examples (audio segments) included in each mini-batch during training.
    *   **Default**: `50`

*   `--iter_num` / `-it`:
    *   **Description**: If specified, this value overrides `--batch_size`. It sets the batch size dynamically such that a total of `iter_num` batches are processed per epoch. This can be useful for datasets of varying sizes.
    *   **Default**: `None`

*   `--learn_rate` / `-lr`:
    *   **Description**: The initial learning rate for the optimizer (e.g., Adam).
    *   **Default**: `0.005`

*   `--init_len` / `-il`:
    *   **Description**: For recurrent neural network (RNN) models, this specifies the number of initial sequence samples to process before starting weight updates at the very beginning of training. This helps initialize the hidden state of the RNN.
    *   **Default**: `200`

*   `--up_fr` / `-uf`:
    *   **Description**: For recurrent models, this is the number of audio samples to process between successive weight updates during the training process.
    *   **Default**: `1000`

*   `--cuda` / `-cu`:
    *   **Description**: Integer flag (0 or 1). If set to `1`, the script will use an available CUDA-enabled GPU for training. If set to `0`, it will force CPU usage.
    *   **Default**: `1` (Uses GPU if available)

*   `--loss_fcns` / `-lf`:
    *   **Description**: A dictionary specifying the loss functions to use and their respective weights. This can be provided as a string representation of a Python dictionary.
    *   **Default**: `{'ESRPre': 0.75, 'DC': 0.25}` (Error-to-Signal Ratio with pre-emphasis and DC loss)
    *   **Example**: `"{'ESRPre': 0.7, 'DC': 0.1, 'MAE': 0.2}"`

*   `--pre_filt` / `-pf`:
    *   **Description**: Specifies a pre-emphasis filter to apply to the audio signals before calculating certain losses (like ESRPre).
    *   **Options**: `high_pass`, `folded_differentiator`, `A-weighting`, `A-weighting-lp`, or a path to a CSV file containing FIR filter coefficients.
    *   **Default**: `high_pass`

*   `--val_chunk` / `-vs`:
    *   **Description**: The chunk size (number of samples) for processing validation data. This helps manage memory usage when evaluating long audio files.
    *   **Default**: `100000`

*   `--test_chunk` / `-tc`:
    *   **Description**: The chunk size (number of samples) for processing test data.
    *   **Default**: `100000`

*   `--model` / `-m`:
    *   **Description**: Specifies the neural network architecture to use for training.
    *   **Options**: `SimpleRNN`, `RecNet`, `GatedConvNet`, `AsymmetricAdvancedClipSimpleRNN`, `ConvSimpleRNN`
    *   **Default**: `SimpleRNN`

*   `--input_size` / `-is`:
    *   **Description**: The number of input channels for the model. For standard mono audio, this is `1`. **Crucially, for models trained with conditioning parameters, this value is automatically calculated and set by the script to `params['n'] + 1` if `params['n']` is defined in the JSON configuration file (see JSON section below).**
    *   **Default**: `1`

*   `--output_size` / `-os`:
    *   **Description**: The number of output channels from the model. Typically `1` for audio modeling tasks (predicting a single audio waveform).
    *   **Default**: `1`

*   `--num_blocks` / `-nb`:
    *   **Description**: For architectures like `RecNet` or `GatedConvNet`, this defines the number of stacked recurrent or convolutional blocks.
    *   **Default**: `3`

*   `--num_layers` / `-nl`:
    *   **Description**: The number of layers within each recurrent or convolutional block (e.g., layers in an LSTM cell, or convolutional layers in a GatedConvNet block).
    *   **Default**: `1`

*   `--hidden_size` / `-hs`:
    *   **Description**: The size of the hidden state in recurrent units (e.g., LSTMs, GRUs) or the number of channels in convolutional layers.
    *   **Default**: `8`

*   `--kernel_size` / `-ks`:
    *   **Description**: The kernel size for convolutional layers used in models like `GatedConvNet` or `ConvSimpleRNN`.
    *   **Default**: `3`

*   `--dilation_growth` / `-dg`:
    *   **Description**: The growth factor for dilation rates per layer in dilated convolutional models (e.g., `GatedConvNet`). A factor of `2` means dilations might go 1, 2, 4, 8, etc.
    *   **Default**: `2`

*   `--unit_type` / `-ut`:
    *   **Description**: The type of recurrent unit to use in RNN-based models.
    *   **Options**: `LSTM`, `GRU`, `RNN` (standard Elman RNN)
    *   **Default**: `LSTM`

*   `--skip_con` / `-sc`:
    *   **Description**: Integer flag (0 or 1). If set to `1`, a skip connection is added from the input of the model directly to its output. This can help with gradient flow and learning identity mappings.
    *   **Default**: `1` (Uses skip connection by default)

*   `--clip_position` / `-cp`:
    *   **Description**: A code (integer) that determines the position of the clipping unit within the `AsymmetricAdvancedClipSimpleRNN` model architecture.
    *   **Default**: `0x00`

### JSON Configuration File Structure

The `dist_model.py` script can load its configuration from a JSON file specified using the `--load_config` argument. The keys in this JSON file should correspond to the command-line argument names (without the preceding `--` or `-`). For example, `learn_rate` in JSON corresponds to `--learn_rate` or `-lr`.

A JSON configuration file might look like this:

```json
{
  "device": "my_conditioned_pedal",
  "file_name": "pedal_data_conditioned",
  "samplerate": 48000,
  "params": {
    "n": 2
  },
  "model": "SimpleRNN",
  "input_size": 3, // Often derived automatically from params.n
  "hidden_size": 16,
  "unit_type": "GRU",
  "num_layers": 1,
  "learn_rate": 0.002,
  "epochs": 1500,
  "batch_size": 64,
  "loss_fcns": {
    "ESRPre": 0.8,
    "DC": 0.2
  }
  // ... any other valid command-line arguments can be included
}
```

#### Key JSON Fields and Influence of Conditioning (`params['n']`)

*   **`params` (object)**:
    *   **`n` (integer)**:
        *   **Description**: This field is **critical** for training models with conditioning parameters. It **must** be set to the number of conditioning parameters that were included in the input data by the `prep_wav.py` script (or a similar preprocessing step). For example, if the input audio was prepared with two conditioning parameters (e.g., "gain" and "tone"), `n` should be set to `2`.
        *   **Effect on Model Input Size**: The `dist_model.py` script uses the value of `params['n']` to automatically determine the `input_size` for the neural network. Specifically, it sets `args.input_size = int(args.params['n']) + 1`.
            *   If `params['n']` is `2`, `input_size` will become `3` (1 channel for the audio signal + 2 channels for the conditioning parameters).
            *   If `params['n']` is not present or is `0`, `input_size` will default to `1` (assuming standard mono audio input), unless explicitly overridden by the `input_size` argument.
        *   **Example**: If `prep_wav.py` used `n=3` conditioning parameters, then `params: {"n": 3}` should be in this JSON config.

*   **`input_size` (integer, usually top-level)**:
    *   **Description**: While this argument can be set directly in the JSON file (or via the command line), it is **strongly recommended to rely on `params['n']` for conditioned models.** If `params['n']` is defined and greater than 0, the script will **override** any value explicitly set for `input_size` with the calculated `n + 1`.
    *   **Recommendation**: For conditioned training, set `params['n']` correctly and omit `input_size` from the JSON, or be aware that `params['n']` will take precedence. For non-conditioned training, `input_size` will default to 1 or can be set explicitly if needed (e.g., for stereo inputs, though the script seems primarily designed for mono targets).

*   **`file_name` (string, top-level)**:
    *   **Description**: This **must** match the `file_name` used during the `prep_wav.py` stage (or whatever script generated the processed `.wav` files). This ensures that `dist_model.py` loads the correct input files, which, for conditioned models, will be multi-channel `.wav` files where conditioning parameters are extra channels.
    *   **Example**: If `prep_wav.py` produced `my_data_conditioned-input.wav`, then `file_name` should be `"my_data_conditioned"`.

*   **`samplerate` (integer, top-level)**:
    *   **Description**: The sample rate of the audio data being used for training. This value is loaded from the configuration and used in various parts of the script, including loss function calculations and data loading. It **must** match the sample rate of the data prepared by `prep_wav.py`.
    *   **Example**: `44100`

By correctly setting these parameters, especially `params['n']`, `dist_model.py` can seamlessly adapt its input layer to accommodate the audio signal plus any additional conditioning parameters, enabling the training of more flexible and controllable audio models.

## Conditioned Model Training

This section focuses on the specifics of training models that are conditioned on external parameters, such as "gain" and "tone" for an amplifier model.

### End-to-End Training Process for Conditioned Models (e.g., with "gain" and "tone")

This guide details how to train a neural network model that is conditioned on two external parameters, such as "gain" and "tone". The process involves two main Python scripts: `prep_wav.py` for data preparation and `dist_model.py` for model training. Both scripts are configured primarily through JSON files.

The goal is to create a model that can change its audio processing behavior based on the conditioning parameters provided alongside the input audio.

**Assumptions:**

*   You have a collection of raw audio data consisting of:
    *   **Input files**: The "dry" or unprocessed audio signals (e.g., direct instrument recordings from a guitar).
    *   **Target files**: The corresponding "wet" or processed audio signals (e.g., recordings of the same guitar performance after passing through an amplifier or effects unit where "gain" and "tone" settings were varied).
*   For each input/target audio pair, you have recorded the specific "gain" and "tone" values (or any other parameters you wish to condition on). These values should ideally be normalized (e.g., to a 0.0-1.0 range).
*   You have a CSV file (e.g., exported from a DAW like Reaper) that defines how your raw audio files are segmented into training, validation, and test sets. This CSV might also contain markers for blips (for auto-alignment) or noise regions (if denoising is used).

#### Step 1: Configure `prep_wav.py`

The first step is to prepare your data using `prep_wav.py`. This script will take your raw audio files, resample them, align them (if necessary), and most importantly, embed the conditioning parameters ("gain" and "tone") into the input audio files as additional channels.

Create a JSON configuration file for `prep_wav.py`. Let's name it `config_prep_conditioned.json` and place it in the `Configs` directory.

**Key settings in `config_prep_conditioned.json`:**

*   `file_name` (string): A base name that will be used for the output processed files. For example, `"my_amp_conditioned"`.
*   `samplerate` (integer): The target sample rate to which all audio will be resampled (e.g., `44100` or `48000`).
*   `params` (object):
    *   `csv` (string): Path to your CSV file that defines data splits and markers. Example: `"Configs/Csv/my_audio_regions.csv"`.
    *   `n` (integer): **Set this to `2`**. This is crucial as it tells `prep_wav.py` that there are two conditioning parameters.
    *   `datasets` (list of objects): This is an array where each object defines one pair of raw input and target audio files, along with their associated conditioning parameter values.
        *   `input` (string): Path to the raw input WAV file.
        *   `target` (string): Path to the corresponding raw target WAV file.
        *   `params` (list of floats): **A list containing the two float values for your parameters: `[gain_value, tone_value]`**. The order of these parameters must be consistent across all entries in the `datasets` list (e.g., "gain" is always the first value, "tone" is always the second).

**Example `config_prep_conditioned.json`:**
```json
{
  "file_name": "my_amp_conditioned",
  "samplerate": 44100,
  "params": {
    "csv": "Configs/Csv/my_amp_splits.csv",
    "n": 2, // Signifies two conditioning parameters
    "datasets": [
      {
        "input": "RawAudio/DI_Track1_gain0.2_tone0.3.wav",
        "target": "RawAudio/Amp_Track1_gain0.2_tone0.3.wav",
        "params": [0.2, 0.3] // [gain_value, tone_value]
      },
      {
        "input": "RawAudio/DI_Track2_gain0.8_tone0.7.wav",
        "target": "RawAudio/Amp_Track2_gain0.8_tone0.7.wav",
        "params": [0.8, 0.7] // [gain_value, tone_value]
      }
      // ... more entries for all your raw audio file pairs
      // with their specific gain and tone values
    ]
  }
  // You can also include other top-level arguments for prep_wav.py here,
  // such as "norm: true" or "denoise: true" if needed.
}
```

#### Step 2: Run `prep_wav.py`

Once the JSON configuration file is ready, execute `prep_wav.py` from your terminal. If your config file is in `Configs/config_prep_conditioned.json`, the command would be:

```bash
python prep_wav.py --load_config config_prep_conditioned.json
```
(Assuming `prep_wav.py` is in your current directory or Python path, and `Configs` is also accessible).

**Output of this step:**

*   `prep_wav.py` will read your raw audio files, process them according to the CSV splits, and apply any specified operations like normalization or denoising.
*   New WAV files will be generated and saved into `Data/train/`, `Data/val/`, and `Data/test/` subdirectories.
*   Crucially, the **input WAV files** (e.g., `Data/train/my_amp_conditioned-input.wav`) will now be **3-channel** audio files:
    *   **Channel 1**: The original audio signal.
    *   **Channel 2**: The first conditioning parameter value (e.g., "gain"), repeated as a constant signal for the length of the audio segment.
    *   **Channel 3**: The second conditioning parameter value (e.g., "tone"), also repeated as a constant signal.
*   The **target WAV files** (e.g., `Data/train/my_amp_conditioned-target.wav`) will remain single-channel audio (or however many channels your original target had, typically mono).

#### Step 3: Configure `dist_model.py`

After preparing the data, the next step is to configure the model training script, `dist_model.py`. Create another JSON configuration file for this script, for example, `config_train_conditioned.json` in the `Configs` directory.

**Key settings in `config_train_conditioned.json`:**

*   `device` (string): A unique name for your model experiment (e.g., `"my_conditioned_amp_v1"`). This name will be used to create a directory in `Results` for saving the trained model and outputs.
*   `file_name` (string): **Must exactly match the `file_name` used in `prep_wav.py`'s configuration** (e.g., `"my_amp_conditioned"`). This ensures `dist_model.py` loads the correct multi-channel input files.
*   `samplerate` (integer): **Must match the `samplerate` used in `prep_wav.py`'s configuration** (e.g., `44100`).
*   `params` (object):
    *   `n` (integer): **Set this to `2` again**. This is critical. `dist_model.py` uses this value to automatically calculate and set the model's `input_size` argument to `n + 1` (i.e., `2 + 1 = 3`). This makes the neural network expect 3 input channels (audio + param1 + param2).
*   `model` (string): Choose the neural network architecture you want to train (e.g., `"SimpleRNN"`, `"GatedConvNet"`, `"RecNet"`).
*   `input_size` (integer): You typically **do not need to set this explicitly** in the JSON file if you have correctly set `params['n']`. The script will derive `input_size = params['n'] + 1`. If you were to set it, it should be `3` for this example.
*   Other training and model parameters: Configure `hidden_size`, `unit_type` (for RNNs), `num_layers`, `learn_rate`, `epochs`, `batch_size`, `loss_fcns`, `skip_con`, etc., according to your specific model architecture and training requirements.

**Example `config_train_conditioned.json`:**
```json
{
  "device": "my_conditioned_amp_v1",
  "file_name": "my_amp_conditioned", // Must match file_name from prep_wav.py config
  "samplerate": 44100,             // Must match samplerate from prep_wav.py config
  "params": {
    "n": 2 // Critical: informs dist_model.py about the number of conditioning params
           // This will result in model.input_size being set to 3
  },
  "model": "SimpleRNN", // Or "GatedConvNet", "RecNet", etc.
  "unit_type": "LSTM",  // If using an RNN-based model
  "hidden_size": 24,
  "num_layers": 1,
  "learn_rate": 0.0015,
  "epochs": 2000,
  "batch_size": 32,
  "validation_p": 30, // Early stopping patience
  "loss_fcns": {
    "ESRPre": 0.8,
    "DC": 0.2
  },
  "skip_con": 1
  // ... other model-specific and training settings as required
  // "input_size" is typically NOT set here, as it's derived from params.n
}
```

#### Step 4: Run `dist_model.py`

With the training configuration file prepared, execute `dist_model.py` from your terminal:

```bash
python dist_model.py --load_config config_train_conditioned.json
```
(Again, assuming `dist_model.py` is in your current directory or Python path, and `Configs` is accessible).

**Output of this step:**

*   `dist_model.py` will load the 3-channel input data (audio + gain parameter + tone parameter) and the corresponding single-channel target data from the directories populated by `prep_wav.py`.
*   It will initialize the specified neural network model with an input layer compatible with 3 channels.
*   The script will then train the model using the defined training parameters.
*   Trained model files (e.g., `model.json`, `model_best.pth`), training statistics (like loss curves), and example output audio files will be saved in the `Results/your_device_name/` directory (e.g., `Results/my_conditioned_amp_v1/`).

#### Summary of Parameter Flow for Conditioning

1.  **You define** the specific "gain" and "tone" values (or any other chosen parameters) for each of your raw audio file pairs within `prep_wav.py`'s JSON configuration, specifically in the `datasets[i].params` list (e.g., `[0.2, 0.3]`).
2.  **You inform `prep_wav.py`** that there are two such conditioning parameters by setting `params.n = 2` in its JSON configuration.
3.  `prep_wav.py` processes this information and creates new multi-channel `*-input.wav` files. These files contain the original audio on the first channel and the conditioning parameter values as constant signals on subsequent channels (channel 2 for "gain", channel 3 for "tone").
4.  **You inform `dist_model.py`** that it should expect data with two conditioning parameters by setting `params.n = 2` in its JSON configuration.
5.  `dist_model.py` uses this `params.n` value to automatically set its internal `input_size` variable to `n + 1` (which is `2 + 1 = 3` in this example).
6.  The neural network architecture defined in `dist_model.py` is then constructed with an input layer that accepts 3 channels.
7.  During training, the network learns to map the input audio *and* its associated "gain" and "tone" channel values to the desired target audio.

This end-to-end process enables the training of a single neural network model that can dynamically alter its audio processing behavior based on the provided "gain" and "tone" (or other) conditioning parameters. This is powerful for modeling devices with multiple controls or for creating adaptable audio effects.

### Functionality

The `modelToRTNeural.py` script is a crucial utility designed to bridge the gap between trained neural network models and their deployment in real-time audio processing environments using the RTNeural library. It converts models from their training-time format (either this project's custom Pytorch-based JSON exports or external `.nam` files) into a specific JSON structure (or optionally, an `.aidax` file) that RTNeural can parse and execute efficiently.

#### 1. Overall Purpose

The core objective of `modelToRTNeural.py` is to enable the use of pre-trained neural network models within the RTNeural ecosystem. RTNeural is a library optimized for running small neural networks in real-time, often within audio plugins or embedded systems. To achieve this, models must conform to a standardized format that RTNeural understands. This script performs the necessary parsing of the original model's architecture and weights, and then meticulously reformats them into this target JSON/AIDAX structure.

#### 2. Model Loading and Selection

The script offers flexibility in how models are loaded, catering to different scenarios:

*   **A. Direct Model Loading (via `--load_model` argument):**
    *   When the `--load_model <path_to_model_file>` command-line argument is provided, the script bypasses any configuration-based loading and attempts to convert the specified file directly.
    *   **Supported Input Formats:**
        1.  **Project's JSON Format**:
            *   These are typically `model.json` (model saved at the final training epoch) or `model_best.json` (model that achieved the best validation score) files generated by the `dist_model.py` training script within this project.
            *   The script expects these JSON files to contain:
                *   `"model_data"`: An object holding the model's architectural details, such as `model_type` (e.g., "SimpleRNN"), `input_size`, `hidden_size`, `num_layers`, `unit_type` (e.g., "LSTM", "GRU"), and `skip` (for skip connections).
                *   `"state_dict"`: An object containing the learned weights and biases of the model, keyed by layer names (e.g., `rec.weight_ih_l0`, `lin.bias`).
            *   Currently, for models from this project's format, the script explicitly supports conversion if `model_data['model_type']` is `"SimpleRNN"`.
        2.  **`.nam` (Neural Amp Modeler) File Format**:
            *   These files originate from the "Neural Amp Modeler" project and are a common way to share guitar amplifier models.
            *   The script parses `.nam` files expecting:
                *   `"architecture"`: A string indicating the model type; the script currently expects this to be `"LSTM"`.
                *   `"config"`: An object containing parameters like `input_size` and `hidden_size`. Note: `num_layers` is often implicitly 1 for many `.nam` LSTMs unless specified.
                *   `"weights"`: A flat list or array of all model weights.
    *   If `--load_model` is used, the output RTNeural JSON/AIDAX file is saved in the same directory as the input model file.

*   **B. Config-Based Model Loading (via `--load_config` argument):**
    *   This mode is active if `--load_model` is *not* provided. The script then relies on the `--load_config <config_name>` argument, along with `--config_location` (to find the config file) and potentially `--results_path` (to specify a custom results directory).
    *   **Process:**
        1.  The script reads the specified training configuration JSON file (e.g., `Configs/MyTrainingConfig.json`). This file provides metadata and model parameters such as `device` (model name), `unit_type`, `hidden_size`, `num_layers`, `skip_con` (used for the `in_skip` field in the RTNeural output), and a `metadata` object.
        2.  It then locates the training results directory. By default, this is `Results/<device>/`, but can be overridden by `--results_path`.
        3.  Within the results directory, it accesses `training_stats.json`. This file contains statistics from the training process, including loss values and sample input/output batches.
        4.  **Best Model Selection**: The script compares the performance of `model.json` (final epoch model) and `model_best.json` (best validation model) by checking `test_lossESR_final` and `test_lossESR_best` values, respectively, within `training_stats.json`. The model with the lower ESR (Error-to-Signal Ratio) is chosen as the "best" model to convert.
        5.  The selected model file (`model.json` or `model_best.json`) is then loaded, similar to how project JSONs are handled in direct loading.
        6.  Additionally, in this mode, `input_batch` and `output_batch` data (if present in `training_stats.json`) are loaded to be included in the output RTNeural file, which can be useful for testing the converted model.

#### 3. Model Conversion Process

Once the model's architecture details and weights are loaded (either directly or via config-based selection), the script begins the conversion into the RTNeural format. This involves constructing a new dictionary layer by layer.

*   **A. Handling `.nam` Files (LSTM specific):**
    *   A dedicated function, `parse_nam_weights`, is employed for `.nam` files that have an `"LSTM"` architecture.
    *   This function meticulously unpacks the flat `weights` array from the `.nam` file. It reconstructs the structured weight components required for each LSTM layer:
        *   Input-to-hidden weights (`weight_ih_lx`)
        *   Hidden-to-hidden weights (`weight_hh_lx`)
        *   Biases (`bias_ih_lx`, `bias_hh_lx`)
        *   Initial hidden state (`h0`) and cell state (`c0`) for the LSTM (though these are not directly used in the RTNeural JSON layer weights, they are parsed).
    *   It also parses the weights and bias for the final linear "head" layer that typically follows the LSTM in `.nam` models.
    *   The parsed weights are then organized into a Python dictionary structure that mimics the `state_dict` format used by the project's own models, allowing the subsequent layer-building logic to be more generic.

*   **B. Layer-by-Layer Construction for RTNeural Format:**
    *   The script iterates `num_layers` times (obtained from the loaded model's configuration) to construct the recurrent part of the model.
    *   **For LSTM Layers (`unit_type == "LSTM"`):**
        *   Input-to-hidden weights (e.g., `rec.weight_ih_l0` from `state_dict`) are retrieved and **transposed**.
        *   Hidden-to-hidden weights (e.g., `rec.weight_hh_l0`) are retrieved and **transposed**.
        *   Input-to-hidden biases (e.g., `rec.bias_ih_l0`) and hidden-to-hidden biases (e.g., `rec.bias_hh_l0`) are retrieved and **summed element-wise** to form a single bias vector for the LSTM layer, as expected by some RTNeural LSTM implementations.
        *   An LSTM layer dictionary is created for the RTNeural output:
            *   `"type": "lstm"`
            *   `"activation": ""` (RTNeural's LSTM layers typically have activations built-in)
            *   `"shape": [null, null, hidden_size]`
            *   `"weights": [transposed_WVals, transposed_UVals, summed_biases]` (WVals are input-to-hidden, UVals are hidden-to-hidden)
    *   **For GRU Layers (`unit_type == "GRU"`):**
        *   Input-to-hidden weights (WVals, e.g., `rec.weight_ih_l0`) are retrieved and **transposed**.
        *   Hidden-to-hidden weights (UVals, e.g., `rec.weight_hh_l0`) are retrieved and **transposed**.
        *   The component matrices within the original WVals and UVals (which are often stacked for reset, update, and new gates) are **reordered** to match the specific gate order expected by RTNeural's GRU implementation (reset, update, new/hidden).
        *   Biases (`rec.bias_ih_l0`, `rec.bias_hh_l0`) are similarly **reordered** and structured into a 2D array (one row for input biases, one for hidden biases, columns corresponding to reordered gates).
        *   A GRU layer dictionary is created:
            *   `"type": "gru"`
            *   `"activation": ""`
            *   `"shape": [null, null, hidden_size]`
            *   `"weights": [reordered_transposed_WVals, reordered_transposed_UVals, reordered_biases]`
    *   **Dense Layer (Head):**
        *   After processing all recurrent layers, a final dense (fully connected) layer is always added. This corresponds to the linear layer (e.g., `lin.weight`, `lin.bias` from `state_dict`) that maps the recurrent layer's output to the model's final output.
        *   The weights (`lin.weight`) are **reshaped** (usually to ensure they are 2D, e.g., `[1, hidden_size]` if the original was flattened).
        *   A dense layer dictionary is created:
            *   `"type": "dense"`
            *   `"activation": ""` (Linear activation is assumed, or subsequent layers in RTNeural handle non-linearities if needed)
            *   `"shape": [null, null, 1]` (Assuming a single output value, common for audio effects)
            *   `"weights": [reshaped_linear_weights, linear_bias_vector]`
*   **Unsupported Types:**
    *   If a model from the project's JSON format is loaded and its `model_data['model_type']` is not `"SimpleRNN"`, the script may not proceed or may handle it incorrectly if the weight naming conventions differ.
    *   If the `unit_type` is neither "LSTM" nor "GRU", the script will print an error and exit, as it doesn't know how to convert other recurrent types.

#### 4. Output File Structure

The script compiles all the processed layer information and metadata into a Python dictionary, which is then saved as a JSON file (or an `.aidax` file if the `--aidax` flag is used). The general structure of this output file is:

```json
{
  "in_shape": [null, null, "input_size_value"],
  "layers": [
    {
      "type": "lstm", // Or "gru"
      "activation": "",
      "shape": [null, null, "hidden_size_value"],
      "weights": [
        // For LSTM: [Transposed_Input_Weights, Transposed_Recurrent_Weights, Summed_Biases]
        // For GRU:  [Reordered_Transposed_Input_Weights, Reordered_Transposed_Recurrent_Weights, Reordered_Biases]
      ]
    },
    // ... (more recurrent layers if num_layers > 1, following the same pattern)
    {
      "type": "dense",
      "activation": "",
      "shape": [null, null, 1], // Example for single output
      "weights": [
        // [Reshaped_Dense_Weights, Dense_Bias_Vector]
      ]
    }
  ],
  // Optional fields below, typically present if loaded via --load_config:
  "in_skip": "skip_con_value",         // Integer, from original model's skip_con/input_skip
  "input_batch": [ /* ... */ ],       // Sample input data from training_stats.json
  "output_batch": [ /* ... */ ],      // Sample target data from training_stats.json
  "metadata": {                        // Metadata from the training config or stats
    "device": "device_name",
    "model_type": "SimpleRNN",
    "unit_type": "LSTM",
    "hidden_size": "hidden_size_value",
    // ... other fields like ESR values
  }
}
```

**Key Components of the Output:**

*   `"in_shape"`: An array defining the expected input dimensions for the model. `input_size_value` is the number of input features (e.g., 1 for standard mono audio, or `n+1` if the model was trained with `n` conditioning parameters). The `null` values typically represent batch size and sequence length, which can be variable in RTNeural.
*   `"layers"`: An array of dictionaries. Each dictionary describes a single layer in the RTNeural model.
    *   `"type"`: String, e.g., `"lstm"`, `"gru"`, `"dense"`.
    *   `"activation"`: String, usually empty (`""`) for RTNeural's built-in recurrent layers, as activations (like sigmoid and tanh) are often an integral part of the layer's cell computation. For dense layers, it's also often empty if linear activation is desired.
    *   `"shape"`: An array describing the output shape of that layer, similar to `in_shape`.
    *   `"weights"`: A list containing the processed weight matrices and bias vectors for that layer, structured as required by RTNeural.
*   `"in_skip"` (optional): An integer value derived from the `skip_con` parameter of the original model. If `skip_con` was greater than 0, this field is included, indicating a skip connection from the model's input.
*   `"input_batch"` / `"output_batch"` (optional): These fields contain sample input and corresponding target output data, typically loaded from `training_stats.json` when using the config-based loading mode. They can be useful for basic verification of the converted model in an RTNeural environment.
*   `"metadata"` (optional): An object containing various pieces of metadata, usually sourced from the training configuration file or `training_stats.json`. This can include the `device` name, original `model_type`, `unit_type`, `hidden_size`, and performance metrics like ESR.

Before saving to JSON, all NumPy arrays holding weights or batch data are converted to standard Python lists to ensure JSON compatibility.
This structured output allows RTNeural to reconstruct the neural network and run it efficiently in real-time applications.

### Input File Formats

The `modelToRTNeural.py` script is designed to convert trained neural network models into an RTNeural-compatible format. It supports two primary input file formats: JSON files generated by this project's own training script (`dist_model.py`) and `.nam` files from the Neural Amp Modeler ecosystem. This document outlines the key structures within these files that `modelToRTNeural.py` specifically interacts with during the conversion process.

#### 1. Project's Model JSON Format (e.g., `model.json`, `model_best.json`)

These files are the standard output from the training pipeline within this project (using `dist_model.py`). They contain both the model's architecture definition and its learned parameters (weights and biases). `modelToRTNeural.py` primarily extracts information from two top-level keys:

*   **`model_data` (object):** This object stores metadata and crucial architectural information about the trained model. The relevant fields for `modelToRTNeural.py` include:
    *   `model` (string): Defines the overall type of the model. The script specifically checks if this is `"SimpleRNN"` to ensure compatibility with its parsing logic for this format.
    *   `input_size` (integer): The number of input features the model expects (e.g., `1` for mono audio, or `n+1` if the model was trained with `n` conditioning parameters).
    *   `output_size` (integer): The number of output features from the model (typically `1` for audio generation/processing tasks).
    *   `num_layers` (integer): The number of recurrent layers stacked in the model.
    *   `unit_type` (string): Specifies the type of recurrent unit used, such as `"LSTM"` or `"GRU"`. This determines how weights are processed for RTNeural.
    *   `hidden_size` (integer): The dimensionality of the hidden state in each recurrent layer.
    *   `skip` (integer or boolean): Represents the `skip_con` (skip connection) parameter from the training configuration. A value greater than 0 (or `true`) indicates a skip connection from the input to the output, which is translated to the `in_skip` field in the RTNeural JSON.
    *   `bias_fl` (boolean, less directly used): Indicates if bias was used in the final linear layer during training. While parsed, this doesn't directly alter the RTNeural structure as bias is assumed present if found in `state_dict`.

*   **`state_dict` (object):** This object is a dictionary containing all the learned weights and biases of the model. The keys are typically named following PyTorch's conventions for layers. `modelToRTNeural.py` looks for specific keys to extract parameters for:
    *   **Recurrent Layers** (for each layer `N` from `0` to `num_layers - 1`):
        *   `rec.weight_ih_l<N>`: The weights for the input-to-hidden connections of the `N`-th recurrent layer.
        *   `rec.weight_hh_l<N>`: The weights for the hidden-to-hidden (recurrent) connections of the `N`-th recurrent layer.
        *   `rec.bias_ih_l<N>`: The bias for the input-to-hidden connections of the `N`-th recurrent layer.
        *   `rec.bias_hh_l<N>`: The bias for the hidden-to-hidden connections of the `N`-th recurrent layer.
    *   **Linear Head Layer** (the final output layer):
        *   `lin.weight`: The weights for the final dense (fully connected) layer.
        *   `lin.bias`: The bias for the final dense layer.

**Example Snippet of a Project JSON Model (`model_best.json`):**
```json
{
  "model_data": {
    "model": "SimpleRNN",
    "input_size": 1,
    "output_size": 1,
    "num_layers": 1,
    "unit_type": "LSTM",
    "hidden_size": 20,
    "skip": 0, // Indicates no skip connection
    "bias_fl": true
    // Other fields like 'sequence_length', 'learn_rate' might be present
    // but are not directly used by modelToRTNeural.py for structure conversion.
  },
  "state_dict": {
    "rec.weight_ih_l0": [ /* Array of input-to-hidden weight values for layer 0 */ ],
    "rec.weight_hh_l0": [ /* Array of hidden-to-hidden weight values for layer 0 */ ],
    "rec.bias_ih_l0": [ /* Array of input-to-hidden bias values for layer 0 */ ],
    "rec.bias_hh_l0": [ /* Array of hidden-to-hidden bias values for layer 0 */ ],
    "lin.weight": [ /* Array of linear layer weight values */ ],
    "lin.bias": [ /* Array of linear layer bias values */ ]
  }
  // Other keys like 'optimizer_state_dict', 'epoch' might be present
  // but are ignored by modelToRTNeural.py.
}
```

#### 2. `.nam` File Format (Neural Amp Modeler)

When a `.nam` file is provided (via the `--load_model` argument), `modelToRTNeural.py` expects it to be a JSON-structured file. The script is specifically designed to parse `.nam` files that represent LSTM-based models. The key fields it interacts with are:

*   **`architecture` (string):** Specifies the neural network architecture. The script currently hardcodes an expectation for this value to be `"LSTM"`. If it's different, the parsing might fail or produce incorrect results.
*   **`config` (object):** Contains configuration parameters for the model defined by `architecture`.
    *   `input_size` (integer): The number of input features for the LSTM model.
    *   `hidden_size` (integer): The number of hidden units in the LSTM layer(s).
    *   `num_layers` (integer): The number of LSTM layers. This is read from the `config` and used by `parse_nam_weights`. (The script later re-reads `num_layers` from its internal `model_data` structure which is populated based on the NAM file, so consistency is important).
*   **`weights` (array of floats):** This is a **flat, 1D array** containing all the numerical values for the model's weights and biases. The script relies on a dedicated function, `parse_nam_weights`, to correctly interpret this flat array. This function segments and reshapes the array into the individual weight matrices and bias vectors for each LSTM layer and the final linear "head" layer.

**Implicit Structure Parsed from `.nam` `weights` by `parse_nam_weights`:**
The `parse_nam_weights` function assumes a specific order and size for the segments within the flat `weights` array. For a model with `num_layers` LSTM layers and a final dense layer, the sequence is generally:

For *each* LSTM layer (from `0` to `num_layers - 1`):
1.  **Input-to-hidden weights (W_ih)**: `hidden_size * 4 * input_size` elements (for LSTM, weights for input, forget, cell, and output gates are often combined).
2.  **Hidden-to-hidden weights (W_hh)**: `hidden_size * 4 * hidden_size` elements (for LSTM, weights for input, forget, cell, and output gates).
3.  **Bias vector (b_ih + b_hh)**: `hidden_size * 4` elements (biases for all gates).
    *Note: The original prompt mentioned separate `hidden_size * input_size` and `hidden_size * hidden_size` which is more typical for a single gate's weights. PyTorch LSTMs and some NAM versions pack all 4 gates together, so `hidden_size * 4` is a common dimension for the gate-combined matrices/biases. The `parse_nam_weights` function must be consistent with the specific NAM file's packing order.*
    *The original prompt also listed initial hidden/cell states. While some `.nam` files might include these, `parse_nam_weights` in this project seems to focus on weights/biases that form the layers for RTNeural conversion.*

After all LSTM layer weights:
4.  **Linear head layer weights**: `output_size * hidden_size` elements (typically `1 * hidden_size` if output_size is 1).
5.  **Linear head layer bias**: `output_size` elements (typically 1).

The `parse_nam_weights` function then reconstructs these parsed segments into a dictionary format that mimics the project's own `state_dict` structure (e.g., assigning to keys like `rec.weight_ih_l0`, `lin.weight`). This allows the rest of the conversion logic in `modelToRTNeural.py` to process the NAM-derived weights in a similar manner to its own JSON model format before finally converting them to the RTNeural layer structure.

A clear understanding of these input formats and the script's expectations is vital for successfully converting models to the RTNeural format and for troubleshooting any issues that may arise during the parsing stage.

### Example Usage Scenario

This section illustrates a practical example of how to use the `modelToRTNeural.py` script. The primary goal in this scenario is to convert a model that was trained using the project's `dist_model.py` script into the RTNeural JSON format, automatically selecting the best performing version of the trained model.

#### Scenario Context

Let's establish the context for this example:

*   **Training Configuration File**: You have previously configured and run a training session using a JSON file named `MyAmpModel_LSTM_Config.json`. This file is located in your `Configs/` directory.
*   **Device Name**: Inside the `MyAmpModel_LSTM_Config.json` file, the `"device"` parameter was set to `"MyAmpDevice"`. This is a common practice to identify and organize different model experiments.
*   **Training Results**: The `dist_model.py` script, using the above configuration, has completed training. The results, which include:
    *   `model.json` (the model from the final training epoch)
    *   `model_best.json` (the model that achieved the best score on the validation set)
    *   `training_stats.json` (containing loss metrics, metadata, and sample I/O batches)
    have been saved in the `Results/MyAmpDevice/` directory, as per the standard output structure of `dist_model.py`.
*   **Goal**: You now want to convert the *best performing* version of this trained model (`MyAmpDevice`) into an RTNeural-compatible JSON file.

#### Command-Line Example

To convert the model based on the scenario above, you would execute `modelToRTNeural.py` from your terminal like this:

```bash
python modelToRTNeural.py --load_config MyAmpModel_LSTM_Config --config_location Configs --results_path Results/MyAmpDevice --verbose
```

#### Breakdown of the Command

Let's dissect each part of this command:

*   `python modelToRTNeural.py`: This is the standard way to execute the Python script.
*   `--load_config MyAmpModel_LSTM_Config`:
    *   This argument tells the script to operate in its "config-based loading" mode.
    *   It specifies that the base name of the configuration file is `MyAmpModel_LSTM_Config` (the `.json` extension is often implied or handled by the script).
    *   The script will look for this configuration file in the directory provided by the `--config_location` argument.
*   `--config_location Configs`:
    *   This argument informs the script that the configuration file (`MyAmpModel_LSTM_Config.json`) is located within the `Configs/` directory relative to where the script is being run or relative to a predefined base path if the script handles that.
*   `--results_path Results/MyAmpDevice`:
    *   This argument explicitly tells the script where to find the training outputs associated with the `MyAmpModel_LSTM_Config`. Specifically, it will look for `training_stats.json`, `model.json`, and `model_best.json` inside the `Results/MyAmpDevice/` directory.
    *   While the script can often infer this path if `device` is correctly set in the config and the `Results` directory is standard, providing it explicitly ensures clarity and correctness.
*   `--verbose` (Optional):
    *   This flag enables detailed logging to the console during the script's execution. You'll see messages about which files are being loaded, what parameters are being parsed, which model is selected as "best," and the progress of the conversion. It's highly recommended for verifying the process and for troubleshooting if issues arise.

#### What the Script Does (Based on the Command)

1.  **Reads Configuration**: The script starts by loading and parsing `Configs/MyAmpModel_LSTM_Config.json`. From this, it extracts model architecture details (like `unit_type`, `hidden_size`, `num_layers`, `skip_con`) and other metadata.
2.  **Accesses Training Statistics**: It navigates to `Results/MyAmpDevice/` and reads `training_stats.json`.
3.  **Determines Best Model**: By comparing the `test_lossESR_final` (associated with `model.json`) and `test_lossESR_best` (associated with `model_best.json`) values found in `training_stats.json`, the script decides which of the two model files represents the better performing model.
4.  **Loads Chosen Model**: It loads the selected model file (e.g., `Results/MyAmpDevice/model_best.json`). This file contains the model's architecture (`model_data`) and learned weights (`state_dict`).
5.  **Gathers Additional Data**: The script also extracts `input_batch`, `output_batch` (sample data), and enriches the `metadata` (e.g., by adding the chosen model's ESR) from `training_stats.json`.
6.  **Converts Model**: The core conversion logic is then applied. The script transforms the model's layers and weights into the structure required by RTNeural (as detailed in the functionality documentation).
7.  **Saves Output**: Finally, the converted model is saved to a new file.

#### Expected Output

*   **Output File Name**: By default, the output file containing the RTNeural-compatible model will be named `model_rtneural.json`.
*   **Output File Location**: This file will be saved in the directory that was specified by the `--results_path` argument (or inferred from the configuration). In this specific example, the output file will be located at:
    `Results/MyAmpDevice/model_rtneural.json`
*   **Alternative Output (with `--aidax` flag)**: If you had included the `--aidax` (or `-ax`) flag in your command:
    ```bash
    python modelToRTNeural.py --load_config MyAmpModel_LSTM_Config --config_location Configs --results_path Results/MyAmpDevice --verbose --aidax
    ```
    Then the output file would instead be named `model_rtneural.aidax` and located at `Results/MyAmpDevice/model_rtneural.aidax`.

This example covers a typical use case where you want to convert the best model from a completed training run. For converting a specific, standalone model file (like a particular `.json` or a `.nam` file), you would use the `--load_model <path_to_your_model_file>` argument instead. In that case, arguments like `--load_config` and `--results_path` would be ignored, and the output RTNeural file would be saved in the same directory as the input model specified by `--load_model`.
